# 下单模板实施与本地验证

日期：2026-10-14。基于 `d8db912`，按人工审核确认的方案实施。验证只使用合成账号、地址、订单模型及临时数据目录，不向 Apple 发起真实加购、下单或支付。

## 已实现

- 每个账号独立保存多份模板，支持新增、草稿、复制、编辑、删除、默认模板和重启恢复。
- 从旧购买参数与快捷地址导入；原数据文件格式和临时购买接口保留。导入后必须补充订单总额上限。
- 送货模板配置地址来源、完整省市区与街道、配送服务规则、运费上限；自提模板配置城市、门店顺序、取货人及最早 / 限定时间范围。城市和门店列表来自内置的 Apple 中国大陆官方目录，详见 [门店多选说明](PICKUP_STORES.md)。
- 联系人、个人电子发票、支付宝、等待到货及有顺序的同机型 SKU 替代白名单纳入模板。
- Rust 在启动时固定保存版本的快照，拒绝浏览器直接提供执行快照和重复的活动下单任务。过期 revision 不能覆盖新版本。
- worker 在网络操作前校验模板，业务信息写入任务私有配置；模板执行不回退到 `text/select/confirm` 提示，缺字段或无法匹配就停止。
- 使用官网实时选项和带签名的取货时段，核对 SKU、数量、收货安排及金额上限后单次提交；结果不明不重放创建订单请求，二维码失败沿用原订单恢复机制。
- 所选门店按顺序切换，全部不可用后才尝试白名单 SKU；关闭等待及替代的模板在所选门店全部不可用时结束。页面提供模板摘要与订单创建总耗时。

## 已确认的原有回归失败

以下失败均用 `git show HEAD` / 临时解包的原始源码独立复现，未修改相关原有业务逻辑：

- worker：`QuantityTests.test_partial_add_failure_does_not_start_checkout`。夹具购物袋包含无移除入口的其他商品，实际先触发购物袋清理检查，用例却期待数量上限错误。
- 界面：`credentials and leading-zero codes stay with the selected account`。期望不记住密码，原界面默认记住。
- 界面：`purchase presets belong to one account`。浏览器已保存购买值优先于之后修改的旧预设。
- 界面：`cancel remains at the operation's top right for prompts and running states on narrow screens`。取消后的任务展示与用例期待的状态文本不一致。

## 使用边界

账号需提前准备登录。Apple 临时设备 / 短信验证及联系人验证不能预先写入模板；官网要求而未提供的证件后四位、未知配送金额或无法比较的送达日期会停止，并提示调整模板。当前仅支持支付宝与个人电子发票，自动替代仅支持所选门店下的同机型白名单。

模板文件使用新增的 `schema_version: 1` 格式，不迁移或覆盖旧配置；本地 IPC / HTTP 增加模板命令，保留原有接口。未新增依赖，未提交、推送或发布。
