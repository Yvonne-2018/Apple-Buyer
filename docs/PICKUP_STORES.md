# 自提城市、门店多选与顺序切换

## 数据来源

2026-10-14 读取 [Apple 中国大陆直营店目录](https://www.apple.com.cn/retail/storelist/)，保存 **25 个城市、49 家直营店** 至 `worker/data/apple-retail-cn.json`。目录包含编号、名称、城市、省份、地址和官方门店链接，以及来源和采集日期。范围与项目对接的中国大陆商城一致；港澳台使用不同商城，未混入 CN 自提选项。

官网 HTML 同时带有全球及重复展示数据，更新脚本只取 `zh_CN` 的 `state.store`，拒绝缺字段及重复编号。更新方法：

```sh
python3 scripts/update_retail_stores.py
# 或读取已经下载的同一官方页面：
python3 scripts/update_retail_stores.py --html /absolute/path/apple-storelist.html
```

刷新目录后重新构建。前端直接引用同一 JSON，worker 从内置数据读取；`build_worker.py` 和 `build_web.py` 都将目录加入 Python 发行包。门店营业或库存变化仍以官网当前结账响应为准；目录不缓存库存、会话或时段签名。

## 操作与执行顺序

1. 在模板或临时购买中选择“门店自提”，从城市列表选择城市。
2. 勾选当前城市的一家或多家门店。初始优先级按勾选次序，使用上移 / 下移调整，或移除某家门店。更换城市后清空门店，避免跨城市混选。
3. 模板保存后，摘要用箭头展示门店顺序；临时购买也按账号保存在本机。
4. 下单查询该城市官网实时门店列表（请求全部门店），依次检查所选编号。当前结果不含该门店、明确不可取货、选店时明确失效或没有符合时间规则的时段时，继续下一家。
5. 每次选店重新确认服务端选中编号和该门店当前时段签名。只选择用户勾选的门店。接口错误、状态未知、签名缺失或门店失配停止，不作为缺货继续执行。
6. 原 SKU 的全部所选门店不可用时，才尝试允许的同机型替代 SKU；保持 SKU 优先、门店次序其次。库存查询按门店批量读取候选 SKU，以减少请求，最终仍由结账确认。
7. 未开启替代及等待时停止；开启等待则每轮查询完成后等待 2 秒，从原顺序重新尝试。创建订单结果不明不切店重下，仍需先查询已有订单。

## 配置兼容

模板 `pickup` 和临时购买 `checkout_preferences` 增加有顺序的 `store_ids: string[]`，例如 `["R580", "R502"]`（成都太古里 → 成都万象城）。非空列表必须无重复且全部属于配置城市；`store` 保留为首选编号以兼容现有字段。模板格式继续使用本次新增的 `schema_version: 1`。

缺少 `store_ids` 的旧单门店模板仍可执行。界面按编号或精确名称（兼容 Apple 前缀、空格和城市的“市”后缀）识别旧值，保存后写入列表；不能识别时提示重新选择，不猜测门店。读取新列表的前后端需一并更新，旧二进制因严格字段检查会拒绝新字段。未新增依赖，未修改锁文件或数据库。
